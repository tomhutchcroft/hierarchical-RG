    How this wiki is checked

    seven checks, all of them cheap enough to run on every change

    A claim is worth what its checks are worth, so here is what is checked and with what. The scripts are in the repository under tools/; none of them needs the network, and the site build itself needs only the Python standard library.

    ScriptChecksWhat that means
    check_wiki.pythe sourcesfront matter, the section structure, the tag ledger, internal links and section fragments, citation keys, the reading maps and the partition of the articles into parts
    preview.pythe sitebuilds the site from the sources, and refuses an unknown figure or simulation name rather than silently dropping it
    check_site.pythe linksevery local href, src and stylesheet url() in the built site, including fragments
    test_math.pythe formulasrenders every formula through KaTeX with errors fatal, so an unsupported macro fails the build instead of a reader's page
    test_sim.pythe browser codeloads the simulation script in quickjs and compares it against the Python reference, bit for bit where the arithmetic is deterministic
    numeric_checks.pythe displayed identitiesassertions of the articles against direct computation on finite blocks: eigenvalues, thresholds, sums, laws and bounds
    preview.py --checkthe committhe site in the repository is exactly what the sources build to, so a stale page cannot be published

    Two limits are worth stating. The checks establish that the statements are internally consistent with the computations and that the site is well formed; they do not establish that a proof is correct, which is a reader's job. And nothing here renders a page in a browser: the formulas are checked through KaTeX and the browser code through quickjs, but how a page looks is not verified by any script.
